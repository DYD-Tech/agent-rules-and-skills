# 项目仓库结构模块设计

本模块统一各种项目共有的文件归属与保留边界，不规定源码、测试和构建目录。常驻规则处理日常存放；技能在初始化、接入或明确整理时执行范围判断、最小调整与验证。不每轮建树、扫描或生成分类报告。

核心边界：doc 根仅 README 和分类目录；agent-workspace 按任务隔离，ref 保存本地参考，两者不进 Git；可复用工具与长期结论及时进入 tools 和相关文档。工具必须位于固定位置的输出可保留，不以整理破坏生态惯例。新分类按需建立，已有结构只在授权范围迁移。

tasks-and-prompt 由用户自行放入已准备的 PRD 或详细计划，不是代理聊天归档。代理不写、不批注、不移动、不修正过时内容。用户为当前任务指定时作为输入；明确续做仍属当前任务。之后原件是历史证据，不能仅因目录存在或检索命中而继续约束后续开发。实际进度与现行要求另行维护，不修改原件、不建立额外状态台账。

本模块可独立安装，无强制依赖；架构和日志模块选用后维护各自内容。英文规则与技能是唯一运行来源，中文对照供维护者阅读。现有仓库仅接入规则及忽略项，不创建所有空目录或迁移历史文件。

目录命名：优先遵循用户明确的项目命名偏好及已有等价位置；没有既有名称的新分类，中文项目用中文名，英文项目用英文名。一次回复切换语言不改变项目约定。不创建两套语言目录，不在未要求迁移时重命名已有路径。README.md、AGENTS.md、doc/、tools/、agent-workspace/、ref/、tasks-and-prompt/ 等标准入口与通用路径保持原名。其他项目语言按用户偏好和既有约定命名。

目录即文档：规则要求创建文件时判断用途、读者与保留方式，优先复用职责匹配的分类，必要时新建。技能提供可检查的结果标准：路径名称说明内容，同层分类依据一致，相关文件有可预期位置；导航按需维护，不新增每轮扫描、分类报告或逐目录 README。通用目录表不是封闭清单，也不覆盖工具固定路径和用户原件保护。

README 不是目录的必备附件。项目入口和 doc 总导航保留；其他目录先靠清晰命名与层级表达组织，仅为尚未被合适入口覆盖的阅读顺序、用法或重要约束新增说明。不重复目录清单、不制造多层导航，也不因此清理已有 README 或写入只读材料目录。
