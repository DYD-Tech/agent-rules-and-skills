# 模块目录、代理安装与文档分工

日期：2026-10-28。状态：0.3.0 已实现目录、指令流程和日志模块；不是已实现自动安装程序，也未完成跨客户端安装实测。

## 用户体验与组织

用户给一个仓库链接并选择模块，代理读取 README → INSTALL.md → catalog/modules.json，获得规则、技能、来源和触发条件。清单是模块组成的依据；中文目录供浏览，别名和标签支持查找。当前四项可独立选用，没有强制依赖。

每个模块可以包含多份规则和技能。安装时保持文件独立，在目标代理的入口中组织加载，避免重新措辞合并导致政策漂移。需要的技能和其激活规则作为一个选择交付，用户不用分别记住两种资源。

当前用一个 JSON 文件容纳四项，易读也方便工具解析。模块很多时再按来源拆文件并生成索引，不先建设搜索服务或包管理器。外部技能由上游维护，本仓库保存地址、分支入口和路径；安装时记录实际提交，避免浮动分支被误当成已锁定版本。

## 安装和推荐的边界

选择模块即授权安装它描述的规则与技能到用户指定范围。推荐只列候选，不自动安装。必要依赖与可选搭配分开；解析时检查去重、循环、未知 ID、目标同名冲突。第三方内容本身不能扩展用户授权。

源文件不直接覆盖现有指引，入口维护一个带标记区块。安装记录保存来源、目标和哈希，支持识别本地修改、重复安装、共享文件及卸载归属。没有部署自动更新服务；更新与移除也由用户请求后交给代理执行。

本次读取 skill-installer，借鉴它按仓库路径获取完整技能包并处理目标已存在的做法；没有调用它进行个人安装。该安装器只解决技能获取，不负责本项目的模块选择与多份规则整合。[Codex skills](https://learn.chatgpt.com/docs/build-skills) 和 [Claude Code skills](https://code.claude.com/docs/en/skills) 提供宿主能力依据；跨宿主入口与路径仍须在安装环境核对，安装指南列出的其他官方链接作为核验入口，不表示已在每种客户端实测。

## 当前文档与历史

架构—功能—实现回答“当前是什么、如何工作、为什么这样选择”。当前理由仍有学习价值；应移走的是按日期累积的修改经过和被替代方案，不是删掉所有“为什么”。未实现计划属于需求或任务记录，不冒充当前能力。

开发日志回答“发生了什么变化、当时为何这样改、验证到什么程度”。[Keep a Changelog](https://keepachangelog.com/en/1.1.0/)强调面向人的重要变化记录而非原始 Git 日志，本项目采用这一取舍，不照搬发布管理流程。普通改动集中在未发布区，复杂演变才独立成篇；不为每轮对话建文件。

现有正式架构决策记录可保留在原位置，当前文档链接相关历史。本次将本仓库 changelog 移到 doc/开发日志/，是当前用户明确提出结构调整后的实施，不意味着安装日志模块就全面搬动业务项目的旧文档。

## 外部来源核验

communication-skills 地址由用户此前提供，本地配套入口及安装说明已读取。本次 web 工具获取 GitHub 页面失败，未确认远端当下内容；目录如实标记这一限制，真正安装时必须取得并检查所选提交。没有镜像外部源码，也未擅自登记未经查看的第三方项目。

后续第三方条目按相同结构加入，说明用途、来源、路径、版本入口、激活方式与依赖。公开可读不等于具备再分发许可；不要凭目录登记宣称内容安全或质量经过验证。

## 验证边界

检查清单结构、路径、技能名称、依赖图和本地链接；对本地模块进行临时项目安装演练，检查两份规则与一个技能的组合、已有指引保留和重复执行。演练由作者执行，不是独立代理盲测，也不证明目标客户端已加载。外部下载、个人范围、不同客户端自动发现和第三方升级冲突仍需后续验证。

## 项目范围的后续完善

默认让规则、技能及触发约定全部随项目，发现目录按实际宿主适配。个人执行副本不改变项目规则的归属。多宿主、版本冲突及云端限制见 [项目优先安装设计](project-first-installation.md)。本地文件演练不构成这些模式的实测。
