# 模块目录

模块是用户选择的安装单位，可以包含规则、技能，或两者。外部模块只登记来源，不复制源码。代理先按名称、别名、标签和说明筛选，再读取选中项的实际文件。

| 模块 ID | 可用中文名称 | 包含内容 | 来源 |
| --- | --- | --- | --- |
| development | 通用规则 | 一份规则 | 本仓库 |
| architecture-features-implementation | 架构功能实现、架构—功能—实现 | 规则＋技能 | 本仓库 |
| development-log | 开发日志 | 规则＋技能 | 本仓库 |
| dyd-tech/clear-communication | 清晰沟通、communication-skills | 每次任务应用规则＋完整技能 | 外部：DYD-Tech/communication-skills |

机器可读目录为 [modules.json](modules.json)。安装、更新和移除按 [安装指南](../INSTALL.md) 执行。可向代理说“从这个仓库安装通用规则、架构功能实现和清晰沟通到当前项目”。只发链接但没说明安装时，先按阅读或咨询请求处理。

## 添加模块

在 JSON 的 modules 中添加一项，保留唯一 ID、名称、别名、标签、用途、来源、完整文件路径、触发方式、必要依赖与可选搭配。外部 ID 使用作者或组织命名空间，例如 `owner/skill-name`，同名技能在安装前检查冲突。

本仓库目前不需要额外依赖；`requires` 只列缺少就不能工作的模块，`suggests` 只用于推荐，不自动安装。新增条目时检查依赖存在且无环。规则路径相对于 source.repo 对应的仓库根；本地来源指当前下载的本仓库。skill_paths 每项是包含 SKILL.md 的完整目录，不是单个文件。

activation.rules 表示要求加载 rule_paths；activation.skills 说明每个技能的触发条件。它们是安装器生成项目入口的依据，不是客户端原生配置。安装时替换为实际目标路径。

外部来源的 ref 默认固定为具体提交，由目录仓库维护其升级；每个业务项目不得自行追随上游浮动分支。来源或版本未锁定时标明限制。安装同时记录目录仓库与外部源码仓库各自的提交。先检查选中版本的内容、授权声明和适用性；登记不代表已安全审计、已获再分发许可或已通过行为测试。第三方资源可以登记，不据此镜像源码、执行脚本或自动安装其额外依赖。无许可证时不擅自推断可再分发。

## 发现与推荐

用户指定名称时匹配 ID 或别名；存在歧义时只问冲突项。用户要求推荐时，结合项目需求给少量候选、理由、来源和安装范围，等待选择或按用户已给出的选装授权执行。不要把整个目录一次性加载进每次开发会话，也不要把 recommendations 写成必需依赖。

真源、fork、适配与项目差异处理见 [同步协议](../SYNC.md)。本仓库的目录可被用户 fork，安装时以用户选定仓库为准，不将本目录位置误认成原作者身份。
