# Agent Rules and Skills

简体中文 | [English](README.en.md)

这是一个跨项目、跨 agent 管理开发规则（rules）和技能（skills）的仓库：集中维护内容与版本，按需安装到不同项目，并适配不同 agent 的加载方式。它让代理以可验证、可维护的标准开发，并通过文档积累项目知识。当前开发版本：0.4.0。本仓库或用户指定的 fork 是可复用内容的唯一维护来源；各项目与各代理的安装结果都应可追溯、可比对，不各自发展成另一套标准。

## 选择如何使用这个仓库

| 使用方式 | 真源 | 可以做什么 |
| --- | --- | --- |
| 仓库所有者或有写权限的维护者 | 本仓库 | 安装、升级项目中的模块；授权 agent 修改、验证并推送源仓库 |
| 直接使用公开仓库 | 本仓库 | 安装模块、升级到本仓库发布的新版本；不能直接写入本仓库 |
| 希望维护自己的通用规则与技能 | 自己的 fork | 在 fork 修改和发布自己的版本，各项目与该 fork 比对 |

“升级安装内容”与“修改源仓库”是两件事。直接使用者无需 fork 就能安装和升级；需要持续维护自己的通用内容时，先 fork 并明确把它选为真源。项目特有约定仍放在项目中，不必为此 fork。向本仓库贡献改进可以通过 fork 提交 PR（合并请求），是否接受由维护者决定。

不要求手动 clone。把远程仓库链接和任务交给 agent，它可按需获取文件或 clone；修改源码时复用已核实的本地检出，没有则在独立目录 clone。仓库链接不提供写权限，已有账号授权也不等于授权本次推送。完整流程见 [源仓库维护](SYNC.md#把改进带回真源)。

## 推荐用法：给代理仓库链接，让它安装

把[本仓库链接](https://github.com/DYD-Tech/agent-rules-and-skills)交给代理，并明确说：

> 请从这个仓库安装“通用规则”“架构功能实现”“开发日志”和“清晰沟通”到当前项目。先读 README、INSTALL.md 和 catalog/modules.json，按模块安装并整合入口，保留已有规则和本地修改，验证实际加载情况。

可以只选其中几项。“通用规则＋架构功能实现”会安装两份规则和一个技能；“清晰沟通”会从独立 communication-skills 仓库获取完整技能，并配置每次任务应用。无需再手工给第二个仓库链接。

如果不知道选什么，可以说：

> 先查看这个仓库的模块目录，结合当前项目推荐合适的模块，说明作用、来源和安装范围；我选择后再安装。

入口为 [模块目录](catalog/README.md)、[机器可读清单](catalog/modules.json) 和 [代理安装指南](INSTALL.md)。这是由代理执行的流程，不是后台自动安装服务；实际网络、权限和宿主能力仍需验证。使用 fork 时，请提供自己的 fork 地址，作为选定的真源。

## 可选模块

| 模块 | 安装内容 | 来源 |
| --- | --- | --- |
| 通用规则 | 开发规则 | 本仓库 |
| 架构—功能—实现 | 当前版本文档规则＋技能 | 本仓库 |
| 开发日志 | 变化记录规则＋技能 | 本仓库 |
| 清晰沟通 | 每次应用入口＋clear-communication 技能 | [外部上游](https://github.com/DYD-Tech/communication-skills) |

模块可以独立选择，推荐项不会自动安装。第三方模块可按目录约定登记，不必复制源码；登记也不代表审计通过或许可已经核实。

## 双语支持

使用文档提供中英文版本；分发的规则、技能入口及运行资源采用一套英文指令，输出语言遵循用户要求。不要按语言安装两份技能或同时加载两套文本。[中文对照与维护约定](doc/中文对照/README.md) 供人阅读，不是运行依赖。历史研究和备份保留原文。模块 ID、安装路径和版本记录不随语言变化。

## 后续更新与汇回

给项目中的代理说：“按安装记录检查这些模块与真源的差异”，或“从选定真源更新已安装模块，保留并说明冲突”。流程见 [SYNC.md](SYNC.md)。只有检查请求时不自动更新；日常开发不每轮联网比对。

真源负责内容，项目文件是锁定版本的安装结果，宿主适配只处理必要格式与加载差异。项目特有要求单独保存；可复用改进回到真源后再同步，临时修补须记录待汇回。外部技能由本目录锁定其上游版本，源码仍由其上游维护。fork 用户可指定自己的仓库为标准，不自动切回原仓库。

[只读检查器](tools/audit_installation.py) 可以判断已登记文件相对安装时是否被改动：

```text
python tools/audit_installation.py --root <目标项目路径>
```

在本仓库运行时使用实际目标项目路径，不对没有安装记录的源码仓库伪造记录。需要 Python 3.10 或更新版本，无第三方依赖；记录格式见 [安装记录](catalog/installation-record.md)。退出码 0 表示所检本地文件未变，1 表示存在差异，2 表示记录或读取错误；0 不代表上游最新。

## 推荐的安装范围

默认把选中的规则、完整技能包和触发约定一起放在项目中，随项目版本管理。技能不必放在个人目录；不同代理只适配各自的项目加载入口。以主要宿主支持的项目目录保存派生文件，已有正确布局保持不变；宿主适配约定集中在 [adapters](adapters/README.md)。

宿主不支持项目技能时，先核对路径配置或纯文本指令读取能力；需要改为个人或账号安装则说明限制并确认对应授权，不把项目要求自动扩大为全局规则。具体选择、同名冲突与云端限制见 [项目优先安装设计](doc/设计/project-first-installation.md)。

## 手动安装

按 [安装指南](INSTALL.md#手动方式) 从清单指定的来源复制规则及完整技能包，再在宿主实际读取的项目或个人指引中加入路径和触发条件。不要复制本仓库根 AGENTS.md，它只指导维护本仓库。
