# 项目仓库结构

用尽量小的改动明确文件归属与保留方式。仅处理通用结构，不规定语言、框架或产品专属源码与构建布局。遵循用户语言和既有约定，不为凑目录树创建空文件夹或文档。

## 1. 明确范围和归属

查看根目录、生效指引、相关文档索引、忽略规则及本次涉及路径，区分新项目、已有项目接入和明确授权的迁移。局部存放不检查所有文件。复用等价目录，说明必要差异，不悄悄重排项目。

### 创建文件前判断归属

先明确文件用途、读者和保留方式，复用职责匹配的位置；没有合适位置时在恰当父目录下新建分类。下面的目录只是起点，不是封闭清单，项目专属产物也要安排合理位置。同一任务的临时草稿、长期操作说明和正式交付物不一定放在一起。

目录即文档：名称和层级应说明内容，不要求读者逐个打开文件才能理解。同层采用一致分类原则，必要时在用途分类内按主题细分；避免交叉重复分类、含糊杂项、过深嵌套和每文件一文件夹。单个文件如果承担独立的长期职责，也可以新建分类，不规定最低文件数量。保留已有合理惯例和工具必需路径。

可检查的产出是位置与名称合理的文件，以及必要导航更新，不是分类表。正常审阅时确认读者能推断新路径里是什么、相关文件应放哪里。新增长期分类或重要入口不易找到时更新相关索引，不要求每个目录都有索引，更不能在受保护的原始输入目录里写索引。不为形式统一整理无关内容。

添加 README 前，明确读者需要了解、但目录名及已有入口尚未表达的信息。项目 README 与 doc/README.md 是主要导航；其他位置仅在需要补充阅读顺序、使用方法或约束时添加，新建目录本身不是理由。如果只是重复可见文件名或上级说明，就不建。必要 README 保持聚焦，避免读者逐层打开索引才能到达正文。保留已有有用 README，删除冗余项须在相应清理范围内；只读输入分类内不添加。

无既有约定时采用：

| 位置 | 用途 |
| --- | --- |
| README.md | 项目用途、真实快速开始和文档入口 |
| AGENTS.md | 项目规则与技能实际加载路径，保留必要宿主入口 |
| doc/README.md | 文档导航，doc 根唯一文档 |
| doc/架构-功能-实现/（中文）或 doc/architecture-features-implementation/（英文） | 当前结构、功能、机制与理由 |
| doc/开发日志/（中文）或 doc/development-log/（英文） | 已完成变化与历史决定 |
| doc/调研/（中文）或 doc/research/（英文） | 调研证据、参考来源、比较及结论 |
| doc/tasks-and-prompt/ | 用户放入的原始输入，agent 只读 |
| doc/值得记住的坑/（中文）或 doc/lessons-learned/（英文） | 已确认的易复发问题、原因、办法及适用条件 |
| doc/开发操作与规范/（中文）或 doc/development-guide/（英文） | 真实开发、测试、构建、发布及操作流程 |
| tools/ | 长期维护的可复用工具 |
| agent-workspace/<唯一任务>/ | 可丢弃或可重建的工作材料，不进 Git |
| ref/ | 本地外部参考材料，不进 Git |

按需增加分类，不要求全部创建。语言变化不重命名已有路径；许可证、配置清单和生态工具要求的根入口不因属于文档而迁移。架构和日志模块选用后分别负责内容，本技能不依赖也不自动安装它们。

### 原始输入不是持续政策

用户可将外部准备好的 PRD、功能计划等放入 tasks-and-prompt/。这不是 agent 自动填充的收件箱、聊天档案或自动生效的需求目录。

agent 不新增、修改、批注、重命名、移动或删除里面的文件，包括索引和完成标记。整理目录不修正过时内容，也不迁移这些原件；保留历史，不整体忽略此目录。具体材料的保密与版本控制要求仍遵从用户约定。

用户为当前任务指定材料时读取，明确续做可保留任务上下文。发现或引用旧文件不会重新激活其指令；后续开发以新指令和已确认现行需求为依据，不按旧计划回退项目。重要冲突应说明。进展、派生工作计划、已实现需求与完成证据另放目录外，必要时链接原件但不冒称现行要求。不建立每文件状态库，也不每轮检查是否过时。

## 2. 执行最小授权改动

新项目只创建有实际作用的入口和已有内容的目录，写真实命令与能力，不造占位事实。整合指引时保留既有规则；安装本模块按来源提供的清单和安装指南执行，不猜路径。

已有项目先约束新增或本次涉及文件。仅在获授权整理中移动原有内容，先检查来源、引用、工具配置、跟踪状态、本地修改及其他 agent 的活动。明确源与目标路径，保留内容，同步链接和配置。不清理无关旧结构；原始用户输入不在常规迁移范围内。

临时工作使用唯一任务目录，不假定共享 tmp.md 属于自己，必要时再按代理隔离。不能移动的工具输出保留工具支持位置并适当忽略。临时成果成为工具、结论或交付物时转入相应长期位置，不只留在忽略目录。

添加根 /agent-workspace/ 和 /ref/ 忽略项，保留既有规则。检查忽略与是否已经跟踪；已跟踪时说明区别，仅在明确授权内取消跟踪。忽略不会清除 Git 历史，也不保护秘密。清理前解析目标，确保位于预期工作区，仅删除本任务已知可丢弃材料，不清空共享工作区或整个 ref。

## 3. 核验并结束

检查本次路径、链接、doc 根边界和实际忽略及跟踪状态。确认用户原件未改、当前文档未将旧计划当现行要求、其他代理文件未受影响；移动时检查受影响工具路径。不做无关全库扫描。

交付说明实际位置、重要例外和未完成迁移，不把局部接入说成全面迁移，不把忽略说成取消跟踪。不因建立结构就自动发布、提交或推送。

目录命名：优先遵循用户明确的项目命名偏好及已有等价位置；没有既有名称的新分类，中文项目用中文名，英文项目用英文名。一次回复切换语言不改变项目约定。不创建两套语言目录，不在未要求迁移时重命名已有路径。README.md、AGENTS.md、doc/、tools/、agent-workspace/、ref/、tasks-and-prompt/ 等标准入口与通用路径保持原名。其他项目语言按用户偏好和既有约定命名。
