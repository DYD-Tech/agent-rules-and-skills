# 开发日志

让维护者了解发生过什么和当时依据，当前产品文档仍描述现状。默认位置 `doc/开发日志/`（中文）或 `doc/development-log/`（英文）；沿用已有 CHANGELOG、开发记录或决策记录，不为相同内容建立第二份。

## 执行

1. 从本次任务、实际改动与验证结果提取值得追踪的变化。区分提议、已实现、已验证、已发布；没有事实依据不补造日期、版本、原因或验证。只有微小无行为影响的润色时无需记录。
2. 在既有日志中按实际完成日期记录，同一天的条目可以共用日期标题。有发布流程的项目沿用既有发布分组。合并同一变化的相关记录，复杂演变可链接单独的决策记录。整理历史时保留有依据的日期。
3. 对照当前说明检查分工：现行行为与设计理由留在当前文档；改动前后经过、废弃方案和历史结论放日志。现有正式决策记录可保留原位置并链接，不强制迁移。旧决定被替代时保留其历史状态及新决定链接，不把历史改成当前规则。
4. 逐句核对事实。删去只交代哪些事没做的句子。如果测试发现了会影响使用的问题，写清触发条件和实际结果，可链接已有问题记录。

## 内容与边界

每条先写具体变化，需要时再补原因和验证结果。沿用项目已有版本号。

用户只要求修正措辞时，不迁移全部历史；用户要求整理旧历史时，保留原始日期和证据，缺失则注明未知。开发记录应归入完整任务，避免同一变化在索引、日记、周报、版本日志中重复。

例如，“保存失败后，编辑内容现在会保留，用户可以重试。已验证正常保存和模拟保存失败两种情况。”

交付时复用任务总结，指出必要记录位置即可；不附固定自检报告。本技能不要求安装其他技能或扫描整库。

语言约定：按用户指定语言输出，否则沿用对话或项目既有语言；英文指令不要求英文或双语输出。保留已有路径和标识，不因切换语言重命名。

目录命名：优先遵循用户明确的项目命名偏好及已有等价位置；没有既有名称的新分类，中文项目用中文名，英文项目用英文名。一次回复切换语言不改变项目约定。不创建两套语言目录，不在未要求迁移时重命名已有路径。README.md、AGENTS.md、doc/、tools/、agent-workspace/、ref/、tasks-and-prompt/ 等标准入口与通用路径保持原名。其他项目语言按用户偏好和既有约定命名。
